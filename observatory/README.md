# Pulseboard SDK on the website

Only the public website (`docs/`, served at <https://chris0jeky.github.io/IdleHarbor/>) loads
Pulseboard. The native C++ executable, the release pipeline, the INI settings and the app's
no-telemetry/no-network promise are unchanged: the app sends nothing.

- `docs/pulseboard.js` is Pulseboard SDK 3.2.0 for project `idleharbor`, generated by
  `observatory/adapters/build-sdk.mjs` in [Chris0Jeky/Pulseboard](https://github.com/Chris0Jeky/Pulseboard)
  (issue #105) and pinned by `observatory.lock.json`. Never edit it; rebuild it with
  `node adapters/build-sdk.mjs idleharbor <this checkout> docs/pulseboard.js` from Pulseboard's
  `observatory/` after deleting the old file, then update the lock.
- `docs/site.js` sends `download.requested` when a visitor chooses the latest-release page
  (`asset: release-page`), the release list (`release-list`) or the source repository (`source`), with
  `version` set to the release tag the page advertises. It is a request, not a completed download,
  installation or active user. Every call is guarded, so the page works when the SDK is blocked.
- The SDK runs only on the registered GitHub Pages origin, never on the Cloudflare mirror and never
  under automation. The mirror's CSP (`docs/_headers`) allows the collector in `connect-src` only.

## What visitors see and what is sent

A **Beta** bar with **Choose** and **OK**, then a small **Beta** button that reopens the choices.

| Category | What | EEA or unknown region | Elsewhere | Kept |
|---|---|---|---|---|
| Usage counts | daily aggregate counts (page views, download-link requests) | on | on | currently 14 days |
| Diagnostics | page timings, JavaScript error summaries, visible time, scroll depth | off until OK | on | 90 days |
| Journeys and product data | random per-tab session id, ordered page and download-link events | off until OK | on | 90 days |

Global Privacy Control or Do Not Track turns every category off with no bar and no request. No names,
e-mail addresses, IP addresses, cookies, page URLs or user agents are stored.

Nothing is stored until Pulseboard admits `idleharbor` in its collector configuration; that is an
owner decision in Pulseboard, not part of this repository.

## Checks

`node observatory/check.mjs` (run in CI) verifies the artifact against the lock and its own header
hash, the collector origin, that it defines `window.Pulseboard` without any request before mount and
stays inert off-origin, the page wiring, that `site.js` survives a missing or throwing SDK, and the CSP.
