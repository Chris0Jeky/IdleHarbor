# Capture manifest validation

The capture tool's pure formatter uses a fixed two-space, LF JSON representation
for its ordered manifest values. It is exercised without launching a window,
changing foreground focus, moving a pointer or recapturing any image.

The original exact-layout/round-trip suite and additional scalar/control-character/
Unicode/integer cases are registered in Test-RegressionScripts for both Windows
PowerShell 5.1 and PowerShell 7. The added evidence check reads the five committed
PNGs, verifies their PNG headers, dimensions and SHA-256 against the manifest, and
rejects duplicate or unsafe filenames. This validates existing evidence identity,
not the present application's appearance or a fresh desktop capture.

The manifest rewrite preserves all existing data and only changes formatting.
The formatter is scoped to the capture tool's string, integer, boolean, null,
ordered-object and array values; it is not a replacement for a general-purpose
JSON serializer. Date/time values in the production manifest are explicitly
converted to strings before formatting. Upstream desktop capture guards, staged
promotion and cleanup remain unchanged.

The continuation handoff records the original worker contribution in PR #113;
that PR's final description records reconciliation and both-edition CI evidence.
Issue #70 concerns serialization. Native capture portability, corner privacy and
harness refactoring remain separately tracked under #49, #50 and #59.

## Capture portability regression (#49)

The native helper initialization reuses the already loaded type, capture-only settings disable
the emergency hotkey, and the owner launch explicitly quotes its configuration path using Windows
native argument rules. The foreground/privacy checks, clean-source checks, staged promotion and
cleanup flow retain their existing behavior.

Run the separate portability regression in both editions:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tests/Test-CapturePortability.ps1
pwsh -NoProfile -File tests/Test-CapturePortability.ps1
```

Thirty checks passed in each edition on 2026-10-08. The suite initializes the real helper twice
in one runspace, checks both generated settings files and launches a harmless temporary .NET
Framework console probe to inspect the actual argv generated by the production owner launch.
The spaced-path case succeeds; an unquoted negative control reproduces the original splitting
defect. Empty values, quotes and trailing backslashes also round-trip. The probe compiler uses
Windows PowerShell 5.1, including when the suite runs in PowerShell 7.

This proof does not launch IdleHarbor or capture the screen. Issue #49 remains open until a real
capture using a spaced temporary/configuration path and two `-Force` captures in the same Windows
PowerShell 5.1 process are observed, with a clean source and no competing owner/UI work. Use a
local output directory outside Git for that proof; committed screenshots are unchanged.
